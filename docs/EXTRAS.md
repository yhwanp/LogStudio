# 확장 기능 (`extras`)

특정 앱의 로그 형식처럼 일부 사용자에게만 쓸모 있는 기능을 LogStudio 본체와 분리해 두는 구조입니다. 확장 기능은 데스크톱 앱을 `--features extras`로 빌드할 때만 포함되며, 릴리스 다운로드에는 포함되지 않습니다. 확장 기능을 추가해도 빌드 옵션은 `extras` 하나로 유지됩니다.

## 켜는 방법

1. 확장 기능이 포함된 앱을 준비합니다. `main` 브랜치에 push될 때마다 실행되는 워크플로가 macOS용 `extras-LogStudio-macos-arm64`와 Windows용 `extras-LogStudio-windows-x64` 아티팩트를 올립니다(실행 요약의 `with extensions (not released)` 링크, 90일 보관). Windows용은 CI가 빌드만 하고 실제로 실행해 확인하지는 않았습니다. 직접 빌드하려면 다음 명령을 씁니다.

   ```sh
   cargo build --release --locked -p logstudio-desktop --features extras
   ```

2. 앱 데이터 폴더의 `extras/` 아래에 확장 기능의 설정 파일 `<id>.json`을 만듭니다.
   - macOS: `~/Library/Application Support/dev.logstudio.desktop/extras/`
   - Windows: `%APPDATA%\dev.logstudio.desktop\extras\`
3. 상단 바에 `확장` 버튼이 나타납니다. 메뉴에서 확장 기능을 고르면 그 기능의 창이 열립니다.

- 설정 파일이 하나도 없으면 `확장` 버튼은 숨겨집니다. 앱을 실행한 채 설정 파일을 만들었다면, 메인 창으로 돌아올 때 버튼이 나타납니다.
- 설정은 메뉴를 열 때마다 다시 읽습니다. 이미 열린 창에는 창을 닫았다 다시 열어야 반영됩니다.
- 설정 파일에 문제가 있으면 메뉴에 `<이름> · 설정 오류` 항목이 고를 수 없는 상태로 나타나고, 그 아래에 파일 이름과 문제가 표시됩니다.
- 메뉴의 `설정 폴더 열기`는 `extras/` 폴더를 만들고 Finder(Windows는 탐색기)에서 엽니다.
- 설정 파일은 64 KiB까지 읽습니다.

## 좌표 궤적 (`track`)

로그 행에 담긴 좌표를 지도에 궤적으로 그리고, 지도와 메인 창의 행을 서로 연결합니다.

- **궤적 클릭:** 궤적에 마우스를 올리면 커서가 바뀌고, 가까운 지점의 행 번호가 표시됩니다. 클릭하면 메인 창의 위 로그에서 그 행을 선택하며, 그 행이 현재 필터 결과에 없으면 그 뒤의 첫 결과로 이동하고 안내합니다.
- **같은 곳을 여러 번 지난 궤적:** 표시에 `이곳을 2번 지남 (1/2)`처럼 통과 횟수가 나옵니다. 처음 클릭하면 가장 가까운 통과(거리가 같으면 시작·끝 지점)를 고르고, 같은 자리를 다시 클릭할 때마다 행 순서대로 다음 통과로 넘어갑니다.
- **키보드:** `[`와 `]`는 선택한 행의 이전·다음 지점으로 이동해 그 행을 선택하고, 지점이 화면 밖이면 지도를 옮깁니다. 방향키는 지도를 옮기고 `+`·`-`는 확대·축소합니다.
- **메인 창에서 선택한 행:** 지도에 그 행 시점의 위치를 파란 십자 표시로 보여 줍니다. 그 행에 좌표가 없으면 그 행보다 앞에서 가장 가까운 지점입니다. 상단 칩에 행 번호와 좌표가 나오며(예: `500행 → 499행 지점 · 52.50000, 13.40000`), 칩의 글자는 선택해 복사할 수 있습니다. `선택한 행으로 지도 이동`이 켜져 있으면 표시가 화면 밖일 때 지도를 옮깁니다.
- **선택 이후 흐리게:** 선택한 행 이후의 궤적은 흐리게 그려, 그 시점까지 지나온 길이 드러납니다.
- **읽는 중인 로그:** 찾은 지점부터 그리며, 실시간 따라가기나 기기 기록으로 늘어나는 로그는 새 행의 지점을 이어서 그립니다. 아직 읽지 않은 행을 선택하면 칩에 `아직 읽지 않았습니다 · N행까지 읽음`이 나오고 위치 표시는 흐려집니다. 메인 창에 다른 로그를 열면 그 로그의 궤적으로 바뀝니다.
- **표시:** 시작 지점은 속이 빈 원, 마지막 지점은 채운 원입니다. `전체 보기`는 궤적 전체가 보이게 지도를 맞추며, 지도를 직접 움직인 뒤에는 자동으로 맞추지 않습니다.
- **창:** 지도 창은 마지막으로 닫았을 때의 위치와 크기로 다시 열립니다(`extras-windows.json`). 그 자리가 지금 연결된 화면 밖이면 기본 위치에 엽니다.

### 설정 (`extras/track.json`)

아래는 형식을 보여 주는 예시입니다. 실제 로그 형식에 맞게 바꿔 쓰세요.

```json
{
  "title": "차량 궤적",
  "marker": "onPositionChanged",
  "latitude": "fix.lat",
  "longitude": "fix.lon",
  "scale": 1e-7
}
```

위 설정은 다음과 같은 행에서 좌표(52.5°, 13.4°)를 읽습니다(합성 예시).

```text
10-25 09:00:01.200  4100  4120 D NavSample: onPositionChanged {"fix":{"lat":525000000,"lon":134000000,"alt":0},"seq":1}
```

| 항목 | 필수 | 설명 |
| --- | --- | --- |
| `marker` | 예 | 좌표가 있는 행을 찾는 문자열(대소문자 구분, 최대 200자). 행에서 이 문자열 뒤에 나오는 첫 JSON 객체를 읽습니다. |
| `latitude`, `longitude` | 예 | JSON 객체 안에서 위도·경도 숫자가 있는 경로. 점(.)으로 나누며, 배열 안의 값은 순서 번호로 적습니다(예: `pos.0`). 문자열로 된 숫자는 읽지 않습니다. |
| `scale` | 아니요 | 읽은 숫자에 곱해 도(°)로 만드는 값. 기본값 `1`. 위 예시처럼 도×10⁷ 정수면 `1e-7`입니다. |
| `title` | 아니요 | 메뉴와 창의 제목(최대 40자). 기본값 `좌표 궤적`. |
| `tiles` | 아니요 | 지도 타일 주소 템플릿. `{z}`·`{x}`·`{y}`가 들어간 https 주소여야 하며, 이 컴퓨터의 타일 서버라면 `http://localhost`나 `http://127.0.0.1` 주소도 됩니다. 기본값은 OpenStreetMap 표준 타일이며, 서브도메인 `{s}`는 지원하지 않습니다. |
| `attribution` | 아니요 | 지도 오른쪽 아래의 출처 문구(최대 200자, 일반 텍스트). 기본 타일이면 `© OpenStreetMap contributors`가, 다른 타일이면 빈 문구가 기본값입니다. |

- 알 수 없는 항목이 있으면 오타로 보고 설정 오류로 표시합니다.
- 위도는 −90~90°, 경도는 −180~180° 범위여야 합니다. 위치를 아직 잡지 못한 기기가 흔히 기록하는 (0, 0)은 지점으로 쓰지 않습니다.
- `marker`가 있지만 좌표를 읽지 못한 행은 상단 상태 줄에 개수만 표시합니다.
- 행 안의 다른 값(예시의 `alt`·`seq`나 기기 자체의 타임스탬프)은 쓰지 않습니다. 지점의 순서와 시점은 로그의 행 순서를 따릅니다.
- 한 로그에서 지점을 최대 2,000,000개까지 읽고, 그 뒤는 읽지 않습니다(상단에 표시).

### 네트워크와 개인정보

- 지도 창만 타일 서버에 접속합니다. 메인 창의 보안 정책(CSP)은 그대로 네트워크를 막습니다.
- **지도에 보이는 영역의 타일을 받으므로, 타일 서버는 궤적이 지나는 지역을 알 수 있습니다.** 로그의 다른 내용은 보내지 않습니다. 회사나 차량 로그처럼 지역이 민감하다면 이 컴퓨터의 타일 서버를 `tiles`에 지정하세요.
- 기본 타일인 OpenStreetMap의 [타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/)을 따릅니다.
  - 지도 창은 앱 이름이 들어간 User-Agent(`LogStudio/<버전> (+https://github.com/yhwanp/LogStudio)`)로 요청합니다.
  - 출처를 지도에 항상 표시하고, 지금 보이는 영역의 타일만 요청합니다.
  - 받은 타일의 보관은 WebView의 HTTP 캐시에 맡깁니다. 그 캐시가 서버의 캐시 헤더를 어떻게 따르는지는 확인하지 않았습니다.
  - 오프라인용으로 미리 받는 기능은 정책에 따라 두지 않습니다.
- 타일을 받지 못하면 그 자리를 빗금으로 채우고, 지도 위에 `지도 타일 N개를 받지 못했습니다`와 확인할 곳(네트워크 연결, 또는 이 컴퓨터의 타일 서버)을 표시합니다. 궤적과 행 연결은 타일 없이도 동작합니다.

## 구조

| 경로 | 역할 |
| --- | --- |
| `extras/src/lib.rs` | 호스트: 확장 목록(`EXTRAS`)과 설정 파일 읽기, 메인 페이지의 `extras` 명령(`list`·`open`·`select`·`reveal`), 확장 창 열기와 위치·크기 기억, `extras` URI 스킴(페이지 파일·`host/*`·`api/*` 응답), 창별 보안 정책 |
| `extras/src/track.rs` | 좌표 궤적: 설정 검증, 행에서 좌표 읽기, 로그 블록을 행 순서로 읽는 백그라운드 작업(따라가기 포함, 읽은 마지막 행 보고), 지도 페이지용 API |
| `extras/web/common/` | 모든 확장 페이지가 쓰는 호스트 클라이언트(`host.js`)와 앱 색상·컨트롤 스타일(`base.css`) |
| `extras/web/track/` | 좌표 궤적 페이지(`index.html`·`track.js`·`track.css`)와 지도와 무관한 계산·문구(`track-model.js`, Node 테스트 대상) |
| `extras/web/vendor/leaflet/` | Leaflet 1.9.4 원본 파일과 라이선스·체크섬([README](../extras/web/vendor/leaflet/README.md)) |
| `dist/extras.js` | 메인 페이지 쪽: `확장` 버튼과 메뉴, 선택한 행 전달, 확장 창이 고른 행 선택 |

- **빌드 분리:** `src-tauri`의 `extras` 기능이 `logstudio-extras` 크레이트를 연결합니다. 이 기능 없이 빌드하면 `extras` 명령의 `list`는 빈 목록을 돌려주므로 `확장` 버튼이 나타나지 않고, 확장 코드·페이지·Leaflet은 실행 파일에 들어가지 않습니다.
- **창과 통신:** 확장 창은 라벨 `extra-<id>`로 열리고 `extras://localhost/<id>/`(Windows는 `http://extras.localhost/<id>/`)에서 페이지를 받습니다.
  - 확장 페이지는 Tauri IPC를 쓰지 않고, 같은 스킴으로 `fetch` 요청을 보냅니다.
  - `host/state`는 메인 창의 로그나 선택한 행이 바뀔 때까지 최대 20초 기다렸다가 답합니다.
  - `host/locate`는 메인 창에 `extras-locate` 이벤트를 보내 행을 선택하게 합니다.
- **보안 경계:**
  - 이 스킴은 그 확장 창이 보낸 GET 요청에만 응답합니다.
  - 페이지 응답에는 확장별 CSP가 붙습니다. 자체 스킴의 스크립트·스타일·요청과, 그 확장이 지정한 이미지 출처만 허용합니다.
  - 확장 창은 자기 페이지 밖으로 이동할 수 없습니다.
  - 앱 명령은 지금처럼 메인 창에서만 받습니다.
  - 메인 창의 창 이벤트 처리(파일 드롭, 창 위치 저장, 닫기 확인)는 다른 창에 적용되지 않습니다.
  - 메인 창을 닫으면 확장 창도 함께 닫히고 앱이 끝납니다.
  - extras 빌드는 `설정 폴더 열기`에서만 외부 프로그램(macOS `open`, Windows `explorer`)을 실행합니다. 대상은 항상 앱 데이터의 `extras/` 폴더이며, 페이지가 경로나 프로그램을 정할 수 없습니다.
- **로그 읽기:** 확장은 코어의 `Engine::shown`과 `Dataset::read_blocks`로 화면에 보이는 로그의 블록을 행 순서로 읽습니다.
  - 인덱싱 중인 블록은 기다렸다 읽습니다.
  - 따라가는 로그는 마지막 블록을 다시 읽어 늘어난 행을 반영합니다.
  - 메인 창의 검색·분석과 함께 돌기 때문에 읽기 스레드는 2개로 제한합니다.

### 확장 기능 추가

1. `extras/src/<id>.rs`에 다음을 둡니다.
   - `ID`, 그리고 설정이 잘못됐을 때 메뉴에 쓸 `NAME`
   - 설정 JSON에서 `Arc<dyn Extra>`를 만드는 `make`
   - `Extra` trait 구현(`title`, `file`, `api`, 필요하면 `image_sources`·`closed`)
2. `extras/src/lib.rs`의 `EXTRAS`에 한 줄을 추가합니다.
3. 페이지 파일은 `extras/web/<id>/`에 두고, `file`에서 `include_bytes!`로 내장합니다. 공용 파일은 `common/…`, `vendor/…` 경로로 불러옵니다. 페이지의 `<title>`은 호스트가 확장의 제목으로 채웁니다.
4. 사용자 문구는 이 문서와 페이지에서 바로 한국어로 씁니다. 테스트와 예시에는 합성 로그와 합성 값만 씁니다.

## 검사

```sh
cargo clippy --locked -p logstudio-desktop --all-targets --features extras -- -D warnings
cargo test --locked -p logstudio-extras
node --test tests/extras.test.mjs
CARGO_TARGET_DIR=target/qa-extras cargo build --release --locked -p logstudio-desktop --features qa,extras
python3 tests/e2e/run.py target/qa-extras/release/logstudio-desktop extras
```

- e2e `extras` 시나리오는 이 컴퓨터에 합성 타일 서버를 띄우므로 외부 네트워크를 쓰지 않습니다. 전체 시나리오와 함께 돌리려면 `--extras`를 붙입니다.
- e2e의 백그라운드 실행에서는 가려진 창이 애니메이션 프레임을 받지 못합니다. 그래서 궤적 캔버스를 다시 그리거나 창 크기에 맞춰 지도를 다시 맞추는 일은 지도가 움직일 때만 일어나며, 시나리오는 캡처 전에 `전체 보기`를 누릅니다. `설정 폴더 열기`는 Finder 창을 띄우므로 e2e에서 누르지 않습니다.
- 측정: `cargo test --release -p logstudio-extras -- --ignored --nocapture measure`는 300만 행(약 246 MiB, 3분의 1이 좌표 행) 합성 로그를 열면서 지점을 함께 읽는 데 걸린 시간을 출력합니다.
  - 환경: Apple M5 Pro, 파일이 OS 캐시에 있는 상태.
  - 결과: 첫 지점까지 2.4 ms, 인덱싱 완료까지 74 ms, 지점 1,000,000개 읽기 완료까지 193 ms.
  - 측정하지 않은 것: 캐시 밖 파일의 첫 읽기, 지도 페이지의 렌더링 시간, Windows 동작.
