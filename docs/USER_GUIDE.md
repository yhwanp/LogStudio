## 화면 구성

| 영역 | 설명 |
| --- | --- |
| 상단 바 | 파일 이름, 크기, 전체 행 수, 읽기 진행률 표시. `다시 열기`, `최근 파일`, `Android 기기`, `?`(단축키 안내·기능 둘러보기) 버튼 제공. 기기 로그를 볼 때는 기록 상태와 `기록 중지`·`저장…` 버튼 표시 |
| 왼쪽 사이드바 | [필터](#필터) 패널(기본값: 자동 숨김) |
| 상단 로그 | 필터가 적용된 로그 목록. 상단 도구 줄에서 [저장된 필터](#저장된-필터)를 선택하고 `열 보기`·`원문 보기` 전환 |
| 하단 영역 | 검색 결과(`북마크` 탭 포함)와 원문 상세 창. 검색 결과나 원문 상세가 열릴 때만 표시 |

- **하단 영역 높이 조절:** 상·하단 경계선을 마우스로 드래그하거나, 경계선에 포커스를 두고 `↑`/`↓`(`Shift`와 함께 누르면 큰 폭으로 이동)를 누릅니다. 경계선을 더블클릭하거나 `Home`을 누르면 기본 높이로 돌아갑니다.
  - 원문 상세만 열려 있을 때는 원문 길이에 맞춰 높이가 자동 조절됩니다.
  - 검색 결과와 원문 상세가 함께 열려 있으면 두 영역이 모두 보이도록 저장된 높이보다 넓어질 수 있습니다.
- **화면 배율(확대·축소):** `Cmd/Ctrl` + `+`/`-`, `Cmd/Ctrl` + 마우스 휠, macOS 트랙패드 핀치 제스처로 화면을 50%~200% 범위에서 조절하고, `Cmd/Ctrl+0`으로 100%로 초기화합니다.
- **다크 모드:** OS 시스템 설정을 자동으로 따릅니다.
- **환경 설정 및 창 상태 유지:** 필터 패널 고정 여부, 열 폭, 하단 영역 높이, 화면 배율, `위 로그 따라가기`, 팁 표시 여부, 창 크기·위치·최대화 상태(`window-state.json`)는 로컬 PC에 자동 저장되어 다음 실행 시 복원됩니다. 이전 모니터 구성이 바뀌어 창이 화면 밖으로 벗어나면 현재 화면 안으로 위치를 보정합니다.

## 팁과 기능 둘러보기

### 처음 쓰는 기능 팁

주요 기능을 처음 사용할 때 해당 컨트롤을 강조하며 간단한 사용 팁을 한 번 표시합니다.

- 파일이 처음 열렸을 때: `?` 버튼과 기능 둘러보기 안내
- 필터 패널을 펼쳤을 때: 레벨 `Alt+클릭`(단독 선택), 쉼표(`,`)로 여러 값 입력하기
- 상단 로그에서 행을 선택했을 때: 다중 행 선택·복사, 북마크 추가, 우클릭 컨텍스트 메뉴
- 검색 결과가 나왔을 때: 상단 로그 연동, `Enter`·`Shift+Enter` 이동
- 첫 북마크를 추가했을 때: `F2`·`Shift+F2`로 북마크 간 이동

팁은 동작 직후 입력이 잠시(0.7초) 멈췄을 때 포커스를 빼앗지 않고 나타나므로 하던 작업을 그대로 이어 갈 수 있습니다. 다른 곳을 클릭하거나 `Esc`·`확인`을 누르면 닫히며, 이미 확인한 팁은 다시 나타나지 않습니다. `팁 그만 보기`를 누르거나 단축키 안내 창(`?`)의 `처음 쓰는 기능에 팁 보기` 옵션으로 언제든 켜고 끌 수 있습니다.

### 기능 둘러보기

단축키 안내 창(`?`)의 `기능 둘러보기` 또는 첫 팁의 `둘러보기`를 누르면 파일 열기, 필터, 저장된 필터, 행 선택·복사, 북마크, 열 폭 조절, 검색, 단축키를 순서대로 안내합니다. 열린 파일이 없으면 샘플 로그를 자동으로 열어 진행하며, `다음`/`이전`(`→`/`←`)으로 이동하고 `Esc`나 `×`로 종료합니다.

## 로그 열기

### 여는 방법

- 파일 선택 창(`Cmd/Ctrl+O`), 드래그 앤 드롭, [명령줄 인자](../README.md#명령줄로-열기), [최근 파일](#최근-파일) 목록으로 파일을 엽니다.
- 연결한 Android 기기의 로그는 파일 없이 바로 기록하며 볼 수 있습니다([Android 기기 로그](#android-기기-로그)).
- macOS에서는 Finder에서 복사한 단일 파일을 `Cmd+V`(Edit → Paste)로 바로 열 수 있습니다(검색 입력란에 포커스가 있을 때는 일반 텍스트 붙여넣기로 동작).
- 클립보드에 복사한 로그 텍스트(최대 25 MiB)도 `Cmd/Ctrl+V`로 붙여넣어 열 수 있습니다. 두 줄 이상이거나 로그 시각으로 시작하는 한 줄이면 로그 텍스트로 인식합니다.
- **열린 로그가 있을 때 붙여넣기:** 이미 열려 있는 로그가 있으면 덮어쓰기 전에 확인 대화상자를 띄워 붙여넣을 텍스트의 줄 수·크기 또는 파일 이름을 보여 줍니다. 기존에 열려 있던 파일의 필터·검색·북마크 상태는 자동 저장되어 나중에 다시 열면 복원됩니다(클립보드 텍스트와 샘플 로그는 제외).
- 파일을 읽는 중에는 `읽기 취소`로 중단할 수 있고, `파일 닫기`로 열린 파일과 진행 중인 작업을 모두 닫을 수 있습니다.

### 열 수 있는 파일

- 단일 파일당 최대 8 GiB(UTF-8 텍스트 및 [DLT 파일](#dlt-파일))까지 엽니다.
- 심볼릭 링크, 일반 바이너리 파일(NUL 바이트 포함), 1 MiB를 넘는 긴 행이 있는 파일은 열지 않습니다. UTF-16 인코딩 텍스트(예: Windows PowerShell에서 `>` 리다이렉션으로 저장한 logcat 파일)나 `.zip`·`.gz` 같은 압축 파일은 열지 않고 변환·압축 해제 안내를 표시합니다.
- **손상된 UTF-8 처리:** 파일 중간에 깨진 UTF-8 바이트가 있어도 행을 버리지 않습니다. 손상된 바이트 구간만 ``로 대체하고 행 번호 옆에 경고 표시를 붙여 원본에 있던 `` 문자와 구분합니다. 원문 상세 창에서 실제 파일 바이트 위치와 16진수(hex) 값을 확인할 수 있습니다.
- **깨진 문자 복원(Mac OS Roman):** 일부 iOS 로그는 UTF-8 문자를 Mac OS Roman으로 잘못 읽은 채 저장되어 `안녕`이 `ÏïàÎÖï`처럼 보입니다. iOS 로그 파일에서는 이런 문자를 원래대로 복원해 보여 주며, 검색·태그 필터·검색어 강조·복사도 복원된 문자를 기준으로 동작합니다. 예를 들어 `ÏïàÎÖï`가 아니라 `안녕`으로 검색합니다. 원문 상세 창 제목에는 `깨진 문자 복원`이 표시되며, 원본 파일과 내보내기 결과는 바뀌지 않습니다.
  - **iOS 로그 판단:** 파일을 열 때 앞부분(64 KiB)에서 iOS 형식 행이 Android 등 다른 형식 행보다 적지 않으면 iOS 로그로 봅니다. 여러 파일을 합쳐 열면 파일마다 따로 판단하고, 붙여넣은 텍스트도 같습니다. Android 로그와 DLT 파일은 복원하지 않으며, 빈 파일을 열어 실시간 따라가기로 iOS 로그를 받는 경우에도 복원되지 않습니다.
  - **일반 문자는 그대로:** `café`, `l’école`, `“인용”`, `5 °C`처럼 원래 있던 악센트·기호는 바꾸지 않습니다. 다만 `Ω`·`Ж`처럼 한 글자만 깨진 경우는 원래 기호와 구분할 수 없어 복원하지 않습니다(`Привет`처럼 단어는 복원).
  - 64 KiB를 넘는 긴 행은 원문 상세·복사에서 64 KiB 단위로 나눠 읽기 때문에, 구간 경계에 걸린 깨진 문자열은 복원되지 않을 수 있습니다.
- 원본 파일은 읽기 전용으로만 다루며 절대 수정하지 않습니다. Windows에서도 다른 프로세스가 기록 중인 파일을 동시에 열 수 있고, 열려 있는 동안 다른 프로그램이 파일을 이름 변경(회전)하거나 삭제하는 것을 막지 않습니다.

### 열린 파일이 외부에서 변경된 경우

- **파일 끝에 내용이 추가됨(기록 중인 로그):** 단일 텍스트 파일을 연 경우에는 기존에 읽은 내용을 유지한 채 상단 바에 `새 줄 있음`을 알립니다. [따라가기](#따라가기)를 켜면 추가되는 줄을 실시간으로 이어서 읽습니다.
- **파일 축소·앞부분 수정·교체(로그 회전):** 파일 크기가 줄어들거나 앞부분 내용이 바뀌면 상단 바의 `다시 열기`(`Cmd/Ctrl+R`)로 파일을 다시 읽어야 합니다([다시 열기](#다시-열기)). 여러 파일을 합쳐 연 경우에는 어느 한 파일이라도 변경되면 다시 열어야 합니다.
- 새 파일을 여는 도중 오류가 발생하면 직전에 열려 있던 정상 파일 화면으로 자동 복구됩니다.

## 인식하는 형식

인식된 로그 줄은 **날짜·시간, PID, TID, 레벨, 태그, 메시지** 열로 분리되며, 형식에 맞지 않는 줄은 원문 행으로 표시됩니다(DLT 파일은 [DLT 전용 열](#dlt-파일)로 표시).

### Android

- **`logcat -v threadtime`** 및 `-v uid` 포함 형식(UID나 사용자 이름은 원문에만 유지)
- **`logcat -v time`**(`06-18 19:24:01.123 D/Tag( 2983): 메시지`) 및 시각이 없는 **`brief`**(`D/Tag( 2983): 메시지`, `-v uid` 포함 가능, TID는 비워 둠, `brief`는 시각 정보가 없어 시간 필터 적용 시 제외됨)
- **Android Studio Logcat 창 기본 복사 형식**(`2026-06-18 19:24:01.123  2983-4241  Tag  com.example.app  D  메시지`) 및 TID 없이 PID만 있는 형식. 패키지명(프로세스 이름)은 날짜·시간 칸에 함께 표시됩니다.
- **날짜·시각 형식:** `MM-DD` 및 연도가 포함된 `YYYY-MM-DD`(`-v year`), 초 이하 소수점 3~6자리 및 9자리(`-v usec`, `-v nsec`)를 지원합니다.

아래 형식은 열로 나누지 않고 원문 그대로 표시합니다.

- 날짜 없이 시각이나 epoch만 표시한 Android Studio Logcat 줄, 필수 칸(PID·태그·패키지)을 숨겼거나 공백이 포함된 태그 줄
- `logcat`의 `long`·`process`·`tag`·`thread`·`raw`·`epoch`·`monotonic`·`zone` 형식 및 ANSI 색상 코드(`-v color`)가 포함된 줄

### iOS

- 날짜·시간과 `process[PID:TID]` 뒤에 태그 없이 메시지만 있는 줄도 iOS 로그로 인식합니다(태그 칸은 비워 둠).
- 레벨은 `process[PID:TID]` 뒤의 첫 대괄호(`[INFO] [Tag] …`, `[I] [Tag] …`)에서 읽습니다.
- 태그 뒤에 레벨이 오는 형식도 인식합니다. 예를 들어 `[demo_plugin][Render][INFO] [ViewRegistry] …`는 태그 `demo_plugin`, 레벨 `Info`입니다. 이때는 `INFO`·`ERROR`처럼 레벨 이름 전체만 레벨로 보고(대소문자 무시), `[A]`·`[I]` 같은 한 글자는 태그로 둡니다.
- 레벨 표기가 없으면 `Unknown` 레벨로 분류하며, 여러 개의 컴포넌트 태그도 그대로 유지합니다.
- 프로세스 이름은 날짜·시간 칸에 함께 표시됩니다.

### 공통 규칙

- **PID / TID:** 숫자가 아닌 문자열로 비교합니다.
- **앞쪽 줄 번호 자동 인식:** 줄 맨 앞에 숫자와 공백이 있고 그 뒤에 유효한 Android/iOS 로그가 이어지면 앞 숫자를 줄 번호로 분리해 인식합니다.
  - 번호가 붙은 줄과 없는 줄이 섞여 있어도 자동 처리되며, 일반 숫자 문장이나 스택 트레이스 줄은 건드리지 않습니다.
  - 기본값은 `자동`이며, 필터 패널 하단의 `읽기 옵션`에서 켜기·끄기를 직접 지정할 수 있습니다.

## DLT 파일

COVESA `dlt-viewer`·`dlt-receive`·`dlt-daemon`이 저장한 `.dlt` 파일(DLT 프로토콜 버전 1, 메시지마다 스토리지 헤더 `DLT\x01` 포함)을 지원합니다. 파일 확장자가 아니라 파일 첫 4바이트로 형식을 판별하며, 전체 파일을 미리 텍스트로 변환하지 않고 화면에 필요한 구간만 즉시 디코딩해 보여 줍니다.

### 열 구성과 표시 규칙

- 메시지 하나가 한 행으로 표시되며, 열은 **행 · 시간 · 타임스탬프 · ECU · APID · CTID · 레벨 · 페이로드**로 구성됩니다.
  - **시간:** 스토리지 헤더의 수신 시각을 현재 PC의 로컬 시간대로 변환해 `YYYY-MM-DD HH:MM:SS.ffffff` 형식으로 표시합니다(`dlt-viewer` 기본 형식과 동일).
  - **타임스탬프:** ECU 부팅 후 경과 시간(초 단위, 0.1 ms 해상도)입니다. 헤더에 값이 없으면 비워 둡니다.
  - **ECU:** 메시지 헤더의 ECU ID를 우선 표시하고, 없으면 스토리지 헤더의 ECU ID를 표시합니다.
  - **레벨:** 로그 메시지의 `Fatal`·`Error`·`Warn`·`Info`·`Debug`·`Verbose`를 표시합니다. 제어(control)·트레이스(trace) 메시지나 확장 헤더가 없는 메시지는 `기타`로 표시하며, 마우스를 올리면 세부 유형(`control:response` 등)을 툴팁으로 보여 줍니다.
  - **페이로드:** `dlt-viewer`와 동일하게 인자들을 공백 하나로 이어 표시하고, 연속 공백·줄바꿈은 공백 하나로 축약하며 NUL은 제거합니다.
    - 정수는 10진수(hex·bin 플래그 지정 시 `0x…`·`0b…`), 실수는 소수점 8자리, 원시 바이트(RAWD)는 16진수, 문자열은 UTF-8로 표시합니다.
    - 배열·구조체·고정소수점 인자나 손상된 인자가 있으면 `!!CORRUPTED MESSAGE!!`로 표시합니다.
    - Non-verbose 메시지는 `[메시지 ID] ASCII|16진`, 제어 메시지는 `[서비스 상태] 16진` 형식으로 표시합니다(FIBEX 변환 미지원).
- `원문 보기`·원문 상세·복사·검색에서는 `날짜 시간 타임스탬프 카운터 ECU APID CTID 세션ID 레벨 페이로드` 형식의 행 텍스트를 사용합니다(빈 필드는 `-`).
- **비정상 바이트 및 미지원 구간:** 손상된 데이터(`!! DLT 메시지가 아닌 데이터...`), 파일 끝에서 잘린 메시지(`!! 잘린 DLT 메시지...`), 버전 2 데이터(`!! 지원하지 않는 DLT 버전 2 데이터...`)는 원문 안내 행 하나로 표시하고 그 뒤의 정상 메시지부터 이어서 읽습니다. 이 행들은 `미인식 줄 포함` 옵션으로 숨길 수 있습니다.
- 유효한 DLT 버전 1 메시지가 하나도 없는 파일이나 스토리지 헤더가 없는 DLT 파일은 열지 않고 사유를 안내합니다.

### DLT 필터

- 태그 입력란이 `ECU · APID · CTID` 입력란으로 바뀝니다. 쉼표로 구분해 입력한 값 중 하나라도 메시지의 ECU·APID·CTID 중 어느 한 곳에 부분 일치(대소문자 무시)하면 매칭됩니다(예: `NAV` 입력 시 APID `NAV`와 CTID `NAVI` 모두 일치).
- DLT에서는 사용하지 않는 PID·TID 입력란, 읽기 옵션, `Assert` 레벨은 숨기고 `Unknown` 대신 `기타` 레벨을 표시합니다.
- 시간 필터는 화면에 표시되는 로컬 수신 시각 기준으로 동작합니다(타임스탬프 값으로는 필터링하지 않음).
- 행 우클릭 메뉴에서 해당 행의 ECU·APID·CTID 값을 포함 조건이나 제외 조건으로 바로 추가할 수 있습니다.

### DLT 내보내기

`내보내기`를 누르면 저장 형식을 선택할 수 있습니다.

- **DLT 원본 (`.dlt`):** 필터·검색 결과에 해당하는 메시지의 원본 바이트(스토리지 헤더 포함)를 그대로 내보내어 `dlt-viewer` 등 외부 도구에서 바로 열 수 있습니다. 메시지가 아닌 손상 바이트 행은 제외하고 건수를 알려 줍니다.
- **텍스트 (`.txt`):** 화면에 표시되는 행 텍스트를 LF 줄바꿈으로 저장합니다.

### DLT 제약 사항

- 실시간 따라가기와 텍스트 로그·DLT 혼합 열기는 지원하지 않습니다(DLT 파일 여러 개를 합쳐 여는 것은 가능).
- 스토리지 헤더가 없는 파일(네트워크 raw 캡처 등), DLT 프로토콜 버전 2, FIBEX 파일 연동은 지원하지 않습니다.

## 여러 줄 로그

JSON 출력이나 스택 트레이스처럼 여러 줄에 걸친 로그는 물리 행 번호를 유지한 채 앞 로그에 묶어 처리합니다.

- **이어지는 줄(Continuation line):** 날짜·레벨 등 로그 필드가 없는 일반 줄은 같은 파일에서 바로 앞에 나온 정상 로그에 속한 줄로 묶습니다.
- **고아 줄(Orphan line):** 파일 맨 앞의 첫 로그보다 먼저 나오는 줄이나, 날짜·시각으로 시작하지만 형식이 깨진 줄(및 그 뒤에 이어지는 줄)은 어느 로그에도 속하지 않는 고아 줄로 다룹니다. 고아 줄은 필드가 없으므로 보기 조건이 설정되면 숨겨지고, `미인식 줄 포함`(기본 켜짐)을 끄면 항상 숨겨집니다.
- **필터와 검색:** 보기·제외 필터 조건은 이어지는 줄에도 소속 로그의 필드를 그대로 적용합니다(예: `태그=AlertsService`로 필터링하면 해당 로그에 이어진 JSON 본문 줄도 함께 남음). 반면 문자열·정규식 검색은 물리 행 단위로 일치 여부를 판정합니다.
- **화면 표시:**
  - `열 보기`에서는 이어지는 줄의 필드 칸을 비우고 메시지 칸 왼쪽에 레벨 색상의 세로 가이드를 표시하며, 같은 로그 안에서는 행 구분선을 생략합니다.
  - `검색 결과`와 `북마크` 목록에서는 이어지는 줄에도 소속 로그의 날짜·PID·TID·레벨·태그를 흐리게 함께 표시해 문맥을 바로 파악할 수 있습니다.

## 필터

상단 로그는 필터 조건에 맞는 행을 보여 주며, 하단 검색은 이 필터 결과 안에서 수행됩니다.

### 필터 패널

- 왼쪽 사이드바의 `필터` 버튼을 누르면 패널이 펼쳐지고, 패널 바깥을 클릭하면 자동으로 접힙니다(입력 중에는 마우스가 밖으로 나가도 닫히지 않음). `자동 숨김`을 끄면 패널을 항상 열어 둘 수 있습니다.
- `초기화`를 누르면 모든 필터 조건과 검색어, 검색 옵션, `미인식 줄 포함` 설정이 기본값으로 돌아가며, 토스트 알림의 `실행 취소`로 되돌릴 수 있습니다.

### 조건 조합 규칙

필터는 **보기 조건(포함)**과 **제외 조건**으로 구성됩니다(DLT Viewer의 positive·negative 필터와 동일한 방식).

- **보기 조건** 중 하나라도 만족하는 줄을 남기고(보기 조건이 없으면 전체 줄 대상), 그중 **제외 조건**에 하나라도 해당하는 줄을 숨깁니다.
- 한 조건 카드 안의 여러 입력란(레벨·태그·PID·TID·시간)은 **모두 만족(AND)**해야 하고, 한 입력란 안에 쉼표로 적은 여러 값은 **하나라도 일치(OR)**하면 됩니다.
- 예: 보기 조건에 `태그: MyApp`과 `레벨: Error·Fatal` 두 개를 추가하고 제외 조건에 `태그: chatty`를 넣으면, `MyApp`의 모든 로그와 다른 태그의 에러 로그를 함께 보면서 `chatty` 태그는 숨깁니다.

| 항목 | 입력 예시 | 일치 기준 |
| --- | --- | --- |
| 레벨 | 레벨 버튼 클릭(`Alt+클릭` 시 단독 선택) | 선택한 레벨에 해당하는 줄 |
| 태그 | `ActivityManager, MyApp` | 입력한 문자열 중 하나라도 포함된 태그가 있는 줄(대소문자 무시, 부분 일치, 최대 32개) |
| PID / TID | `2983, 3120` | 입력한 값 중 하나와 정확히 일치하는 줄(쉼표·공백 구분, 문자열 비교, 최대 32개) |
| 시간 | `06-18 19:24` ~ `19:25` | 시작 시각부터 끝 시각까지(양 끝 포함)에 해당하는 줄 |

- **다중 조건 편집:**
  - 처음에는 보기 조건 1개가 바로 입력란으로 표시됩니다. PID·TID와 시간 입력란은 `+ PID·TID`·`+ 시간` 버튼을 누를 때 펼쳐집니다.
  - `+ 보기 조건 추가`·`+ 제외 조건 추가`를 누르면 조건마다 카드가 만들어집니다(보기·제외 합산 최대 32개). 카드를 클릭하면 편집 입력란이 열리고 나머지 카드는 한 줄 요약으로 접힙니다.
  - 각 카드의 체크박스로 조건을 임시로 끄거나 켤 수 있고, `×`로 삭제할 수 있습니다.
- **맞는 줄이 없는 조건(0건 조건) 표시:**
  - 현재 열린 로그 전체에서 일치하는 줄이 하나도 없는 조건은 카드와 상단 칩 테두리가 점선으로 바뀌고 `맞는 줄 없음`(`줄 없음`)이 표시됩니다. 오타나 다른 파일에서 쓰던 필터 값을 쉽게 구분할 수 있습니다.
- **시간 범위 입력 규칙:**
  - `[MM-DD 또는 YYYY-MM-DD] [HH[:MM[:SS[.소수점 1~9자리]]]]` 형식으로 앞자리부터 필요한 단위까지만 입력하면 됩니다(예: 끝 시각에 `19:25`만 입력하면 `19:25:59.999999999`까지 포함).
  - 시작·끝 모두 시각만 입력하면 날짜와 관계없이 해당 시간대에 적용되며, 끝 시각이 시작 시각보다 이르면 자정을 넘기는 범위로 처리합니다(예: `23:00` ~ `01:00`).

### 필터 칩

- 적용 중인 조건은 상단 로그 제목 옆에 문장처럼 읽히는 칩으로 표시됩니다(보기 조건 사이는 `또는`, 제외 조건 앞에는 `제외` 표시).
- 각 칩을 클릭하면 해당 조건 항목만 바로 해제됩니다.

### 행 메뉴로 거르기

- 로그 행을 우클릭(또는 `Shift+F10`)하면 해당 행의 태그·PID/TID·시각·레벨로 **보기 조건 추가**, **태그 제외**, **원문 복사**, **북마크**를 바로 실행할 수 있습니다(DLT 파일에서는 ECU·APID·CTID 조건 제공).
- 기존 조건을 덮어쓰지 않고 새 조건을 추가하며, 실행 직후 나타나는 알림의 `실행 취소`로 바로 되돌릴 수 있습니다.

### 저장된 필터

자주 쓰는 필터 조건 조합에 이름을 붙여 저장해 두고 다른 파일에서도 바로 불러올 수 있습니다.

- **저장:** 필터 패널 상단의 `저장` 또는 상단 바 `저장된 필터` 메뉴의 `현재 필터 저장…`을 눌러 이름을 지정합니다(최대 60자, 최대 100개, `saved-filters.json`에 저장). 보기·제외 조건(꺼진 조건 포함)과 `미인식 줄 포함` 여부가 저장되며, 검색어는 저장되지 않습니다.
- **적용 및 수정:** 메뉴에서 저장된 필터를 선택하면 즉시 적용됩니다. 적용 후 조건을 변경하면 버튼에 `수정됨`이 표시되며, 메뉴에서 기존 필터에 덮어쓰거나 `저장한 조건으로 되돌리기`, `다른 이름으로 저장…`을 선택할 수 있습니다.
- 텍스트 로그용 필터와 DLT 파일용 필터는 형식별로 구분되어 관리됩니다.

## 검색

검색은 상단 로그의 현재 필터 결과 안에서 수행되며, 일치하는 행을 하단 검색 결과 창에 모아 보여 줍니다. 기본값은 대소문자를 구분하지 않는 일반 문자열 검색이며, 검색창 옆에서 `정규식`과 `대소문자 구분`을 켤 수 있습니다.

- **정규식 문법:** 줄 단위 Rust 정규식을 사용합니다. 전후방 탐색(lookaround)과 역참조(backreference)는 지원하지 않으며, 대소문자 무시는 Unicode simple case folding 규칙을 따릅니다. 한 행당 최대 32개의 일치 구간까지 강조 표시합니다.
- **결과 탐색:**
  - 검색 입력란에서 `Enter`/`Shift+Enter`를 누르면 입력 포커스를 유지한 채 다음·이전 검색 결과로 이동합니다.
  - 검색 결과 목록에서 행을 더블클릭하거나 `Enter`를 누르면 상단 로그의 해당 행으로 포커스를 옮깁니다.
  - `위 로그 따라가기`(기본 켜짐)를 켜 두면 검색 결과에서 행을 클릭하거나 `↑`/`↓`로 이동할 때 상단 로그도 해당 위치로 함께 스크롤됩니다.
- **상단 로그 강조:** 검색에 일치한 행은 상단 로그에서도 행 번호 오른쪽에 노란색 표시줄이 나타나고 일치한 문자열이 하이라이트됩니다(행 번호 왼쪽 파란 표시줄은 북마크).

## 목록 탐색과 복사

상단 로그, 하단 검색 결과, 북마크 목록은 모두 동일한 탐색 및 선택 방식을 지원합니다.

- **행 번호로 이동:** 목록 상단의 `행 번호` 입력란에 물리 행 번호(여러 파일을 합친 로그에서는 `파일번호:행번호`, 예: `2:150`)를 입력해 바로 이동합니다. 해당 행이 필터에 가려져 있으면 그 뒤에 오는 첫 번째 결과 행으로 이동합니다.
- **다중 행 선택:**
  - **마우스 드래그:** 행을 누른 채 위아래로 끌면 연속된 행 범위를 선택합니다(목록 끝 밖으로 끌면 자동 스크롤).
  - **`Shift+클릭`, `Shift+↑/↓/PageUp/PageDown/Home/End`:** 기준 행부터 해당 위치까지 범위를 선택합니다.
  - **`Cmd+클릭`(macOS) / `Ctrl+클릭`(Windows):** 개별 행을 선택에 추가하거나 해제합니다. `Cmd/Ctrl`을 누른 채 드래그하거나 `Shift+클릭`하면 기존 선택을 유지한 채 범위를 추가합니다.
  - **`Cmd/Ctrl+A`:** 검색 결과 및 북마크 목록의 전체 행을 선택합니다(상단 전체 로그에서는 동작하지 않음).
- **복사(`Cmd/Ctrl+C`):** 선택한 행들의 원문을 목록 순서대로 줄바꿈(LF)으로 이어 복사합니다(최대 10,000행, 초과 시 파일로 저장하는 [내보내기](#내보내기) 안내).
  - **행 내부 텍스트 부분 선택:** 단일 행이 선택된 상태에서 행 안의 텍스트를 마우스로 드래그해 긁으면 해당 부분 문자열만 선택·복사할 수 있습니다. 드래그 포인터가 다른 행으로 넘어가면 자동으로 다중 행 선택으로 전환됩니다.

## 원문 상세

목록에서 행을 선택하면 하단 오른쪽에 원문 상세 창이 열리며, 닫기 버튼(`×`)이나 `Esc`로 닫을 수 있습니다.

- 선택한 행이 속한 로그 엔트리 전체(첫 줄과 이어지는 멀티라인 본문 전체)의 원문을 보여 줍니다.
- 한 로그 엔트리는 최대 1 MiB(또는 10,000줄)까지 묶어서 보여 주며, 긴 원문은 64 KiB 구간 단위로 넘기며 볼 수 있습니다.
- **복사 범위 구분:**
  - 원문 상세 창의 `복사` 버튼 및 우클릭 메뉴의 `로그 전체 원문 복사`: 멀티라인을 포함한 해당 로그 엔트리 전체 복사
  - 목록에서 `Cmd/Ctrl+C` 및 우클릭 메뉴의 `행 원문 복사`: 선택한 물리 행만 복사

## 북마크

- 원하는 행을 선택하고 `Cmd/Ctrl+B`를 누르면 북마크가 추가되거나 해제됩니다(최대 1,000개).
- 북마크는 물리 행 번호 기준이므로 필터나 검색 조건을 바꿔도 유지되며, 파일을 다시 열거나 나중에 같은 파일을 열 때도 복원됩니다.
- 북마크가 하나 이상 있으면 하단 검색창 왼쪽에 `검색 결과 | 북마크 N` 탭이 나타납니다.
- `F2` / `Shift+F2`로 상단 로그에서 다음·이전 북마크로 빠르게 이동할 수 있습니다. 북마크 탭에서는 `Delete`(`Backspace`)나 `Cmd/Ctrl+B`로 선택한 북마크를 삭제하고, `모두 복사`로 전체 북마크 원문을 한 번에 복사할 수 있습니다.

## 열 폭

상단 로그, 하단 검색 결과, 북마크 목록은 열 폭을 함께 공유합니다.

- **수동 조절:** 열 머리글 경계선을 마우스로 드래그하거나, 경계선에 포커스를 두고 `←`/`→`(`Shift`로 큰 폭 조절)를 누릅니다.
- **내용에 맞춤:** 열 경계선을 더블클릭하거나(포커스 시 `Enter`), 상단 `열 폭` 메뉴(또는 열 머리글 우클릭)에서 `내용에 맞춤`을 선택하면 현재 화면에 보이는 행 길이에 맞춰 폭을 자동 조절합니다.
- **폭 초기화:** `열 폭` 메뉴의 `폭 초기화`(또는 경계선 포커스 시 `Home`)로 기본 폭으로 되돌립니다.
- 행 번호 열과 날짜·시간 열은 자리수나 마이크로초·나노초 표기가 잘리지 않도록 열릴 때 폭을 자동으로 넓혀 줍니다.

## 내보내기

- 상단 로그와 검색 결과의 `내보내기` 버튼을 누르면 현재 필터링·검색이 완료된 결과 행들을 파일로 저장합니다.
- 텍스트 로그는 원본 바이트와 줄바꿈(CRLF/CR/LF)을 변형 없이 그대로 기록하며, DLT 파일은 `.dlt` 원본과 `.txt` 텍스트 중 선택할 수 있습니다([DLT 내보내기](#dlt-내보내기)).
- 내보내는 도중 `내보내기 취소`로 중단하거나 오류가 발생하면 임시 파일을 정리해 불완전한 파일이 남지 않습니다. 현재 열려 있는 원본 파일 경로에는 덮어쓸 수 없습니다.

## 따라가기

`adb logcat -v threadtime > live.log`처럼 실시간으로 기록 중인 단일 텍스트 로그 파일을 `tail -f`처럼 이어서 읽습니다. 연결한 Android 기기의 로그는 터미널 없이 [Android 기기 로그](#android-기기-로그)로 바로 볼 수 있습니다.

- 상단 로그 도구 줄의 `따라가기` 버튼을 눌러 켜고 끕니다(단일 텍스트 파일을 끝까지 읽은 뒤 활성화되며, 병합 로그·붙여넣은 텍스트·DLT 파일에서는 미지원).
- 켜져 있는 동안 0.5초 간격으로 파일 끝을 확인해 새로 추가된 줄만 이어서 인덱싱·필터링·검색합니다.
- 상단 로그 스크롤이 맨 끝에 있으면 새 줄이 들어올 때마다 자동으로 끝부분을 따라가고, 위로 스크롤해 다른 줄을 보고 있으면 현재 스크롤 위치를 유지합니다.
- 아직 줄바꿈 문자가 기록되지 않은 미완성 마지막 줄은 줄바꿈이 들어와 행이 완성될 때 화면에 반영합니다.

## Android 기기 로그

USB 디버깅을 켠 Android 기기나 에뮬레이터의 logcat을 터미널 없이 실시간으로 기록하며 봅니다. 기록한 로그는 일반 로그처럼 필터·검색·북마크를 쓸 수 있습니다.

### 준비

- 컴퓨터에 adb(Google Android SDK Platform-Tools)가 있어야 합니다. Android Studio를 설치했다면 그대로 쓰며, Android Studio 없이 adb만 설치해도 됩니다.
- adb는 Android Studio 기본 SDK 폴더, `ANDROID_HOME`·`ANDROID_SDK_ROOT`, `PATH`, Homebrew 설치 위치 순서로 찾습니다. 찾지 못하면 기기 메뉴의 `설치 방법 보기…`에서 설치 명령(macOS `brew install --cask android-platform-tools`, Windows `winget install Google.PlatformTools`)과 공식 다운로드 주소를 안내하며, `adb 위치 지정…`으로 압축을 푼 폴더의 adb를 직접 선택할 수도 있습니다.
- Android Studio 등 다른 도구와 함께 쓸 때는 모두 같은 버전의 adb를 쓰도록 맞춥니다. 버전이 다른 adb가 함께 실행되면 adb 서버가 계속 다시 시작되므로, 이를 감지하면 기록을 멈추고 안내합니다.

### 기록하기

- 상단 바의 `Android 기기`(빈 화면에서는 `Android 기기 연결`)를 누르면 adb가 인식한 기기 목록이 나타나고, 기기를 선택하면 바로 기록을 시작합니다. USB 디버깅을 허용하지 않았거나 오프라인인 기기는 이유와 함께 표시합니다.
- **시작한 뒤의 로그만 담습니다.** 기기에 이미 쌓여 있던 로그는 가져오지 않고, 기록을 시작한 뒤 들어오는 로그만 받습니다. 버퍼는 logcat 기본값(main·system·crash)을 쓰며 형식은 `threadtime`입니다.
- 기록 중에는 [따라가기](#따라가기)가 켜져 새 로그가 들어올 때마다 이어서 보여 줍니다. 따라가기를 끄면 화면만 멈추고 기록은 계속되며, 다시 켜면 그동안 들어온 로그까지 따라잡습니다.
- `기록 중지`를 누르면 상태가 `기록 중지됨`으로 바뀌고, 그때까지 기록한 로그를 끝까지 읽어 건수를 확정합니다.
- 상단 바 상태 끝의 `저장 안 됨`은 아직 저장하지 않은 로그가 있다는 뜻입니다. 그동안은 `저장…`이 강조 버튼이 되고, 저장하면 `저장함`으로 바뀝니다. 창이 좁으면 상태 문구는 뒤쪽(기기 이름)부터 줄여 보여 주며, 전체 문구는 상태에 마우스를 올리면 보입니다.

### 연결이 끊겼을 때

- 케이블이 빠지거나 adb 서버가 다시 시작되어 연결이 끊기면 `연결 끊김 · 다시 연결을 기다리는 중 · 기기 이름`으로 바뀌고, 같은 기기가 다시 연결되면 자동으로 이어서 기록합니다. 무선 디버깅처럼 연결 이름(serial)이 바뀌어도 기기 고유 번호로 같은 기기를 찾습니다.
- 같은 부팅 안에서 다시 연결되면 마지막으로 기록한 로그 다음부터 빠지거나 겹치는 줄 없이 이어 붙입니다(끊긴 동안 기기 버퍼에서 밀려난 로그는 되살릴 수 없습니다).
- 그사이 기기가 재부팅되었으면 새 부팅의 첫 로그부터 기록합니다.
- 기기가 목록에 다시 나타났지만 재부팅 뒤 USB 디버깅 허용을 기다리는 등 아직 쓸 수 없으면, `연결 끊김 · USB 디버깅을 허용해 주세요 · 기기 이름`처럼 필요한 일을 먼저 표시하고 허용되는 대로 이어서 기록합니다.
- 다시 연결된 첫 행 위에는 점선과 함께 `11:00:05 연결 끊김 → 11:00:08 다시 연결`처럼 끊긴 시각과 다시 연결된 시각을 표시합니다. 그사이 기기가 재부팅되었으면 `· 기기 재부팅`이 붙습니다. 필터나 검색으로 그 행이 보이지 않으면 다음에 보이는 행에 표시하며, 그 사이에 여러 번 끊겼으면 `연결 끊김 2번`처럼 묶어 보여 줍니다. 이 표시는 화면에만 있고 기록한 로그 원문에는 아무것도 끼워 넣지 않습니다.

### 저장과 임시 파일

- 기록한 로그는 앱의 임시 폴더에 원본 그대로 쌓입니다. `저장…`(`Cmd/Ctrl+S`)을 누르면 지금까지 기록한 로그를 원하는 위치에 원본 그대로 저장하며, 기록 중에도 저장할 수 있습니다. 저장하는 동안에는 버튼이 `저장 취소`로 바뀌어 큰 로그를 저장하다가 멈출 수 있고, 멈추면 저장하던 파일은 남기지 않습니다.
- 저장하지 않은 기기 로그가 열려 있으면 다음과 같을 때 `기기 로그를 저장할까요?`를 묻습니다: 로그나 창을 닫을 때, 다른 파일이나 기기를 열 때, 앱 메뉴에서 종료(`Cmd+Q`)할 때.
- `저장…`을 누르면 파일로 저장한 뒤 진행하고, `저장 안 함`을 누르면 임시 파일을 지운 뒤 진행합니다. `취소`를 누르면 지금 로그를 그대로 둡니다.
- 앱이 기록 중에 비정상 종료되었거나 Dock의 종료·로그아웃처럼 묻지 못하고 종료되어 남은 기기 로그는 다음 실행 때 빈 화면의 `저장하지 않은 기기 로그` 목록에 나타납니다. 열면 상단 바에 `남은 기기 로그 · 저장 안 됨`으로 표시됩니다. 항목을 눌러 열어 저장하거나, `삭제`를 4초 안에 두 번 눌러 지웁니다.
- 기기 로그는 임시 파일이므로 [다시 열기](#다시-열기)와 [작업 복원](#작업-복원) 대상이 아닙니다. 기기 로그는 한 번에 최대 8 GiB까지 기록합니다.
- 8 GiB에 도달하거나 디스크 공간이 부족하거나 adb 문제로 기록이 중단되면, 상단 바가 `기록 중단`으로 바뀌고 로그 위 오류 막대에 중단 이유를 보여 줍니다. 그때까지 기록한 로그는 그대로 남습니다.

## 여러 파일 합쳐 열기

- 파일 선택 창에서 여러 파일을 함께 선택하거나 창에 한 번에 드래그 앤 드롭하면 최대 64개 파일(각 파일 최대 8 GiB, 합산 크기 제한 없음)을 하나의 연속된 로그로 묶어 엽니다.
- 같은 파일을 중복 선택하거나 텍스트 로그와 DLT 파일을 섞어 열 수는 없습니다. 여러 파일 중 하나라도 열 수 없으면 실패한 파일 이름을 안내하고 열기를 취소합니다.

### 합치는 순서

파일 선택 창이나 드래그 앤 드롭으로 여러 파일을 열 때는 각 파일의 앞·뒤 64 KiB에서 로그 시각을 읽어 **시간순으로 자동 정렬**합니다(부팅 직후 시계가 맞춰지기 전의 초기 로그 때문에 순서가 뒤섞이지 않도록 파일 끝부분 시각을 우선 비교하며, DLT는 첫 메시지 시각을 비교).

- 시각 정보가 없거나, 연도가 없는 로그끼리 183일 이상 벌어져 연도 경계를 판단할 수 없거나, 모든 파일의 시각이 같으면 **자연 이름순**으로 정렬합니다. 이때 회전 로그 번호(`.1`, `.2` 등)는 숫자가 클수록 오래된 파일로 판단해 `main.log.2` → `main.log.1` → `main.log` 순서로 잇습니다.
- [명령줄](../README.md#명령줄로-열기)로 여러 파일을 넘겼을 때는 자동 정렬하지 않고 인자로 넘긴 순서를 그대로 따릅니다.

### 합친 로그의 표시

- 행 번호 열이 `파일 · 행` 형식으로 바뀌어 파일 번호 배지와 해당 파일 내 행 번호를 표시합니다(마우스를 올리면 파일 이름과 전체 통합 행 번호 표시).
- 파일이 바뀌는 경계 행 위에는 구분선이 그려지고, 원문 상세 창 제목에도 해당 파일 이름이 함께 표시됩니다.

## 다시 열기

상단 바의 `다시 열기`(`Cmd/Ctrl+R`)는 현재 열려 있는 파일을 같은 경로와 순서로 다시 읽습니다.

- 현재 적용된 필터, 저장된 필터 선택 상태, 검색어와 검색 옵션, 보기 모드, 하단 탭, 북마크, 상·하단 스크롤 위치 및 선택 행을 그대로 유지합니다.
- 파일을 다시 읽은 뒤 기존 북마크 행의 내용이 바뀌었거나 파일 길이가 줄어 범위를 벗어난 북마크가 있으면 알림으로 안내합니다.

| 경로·파일 크기·수정 시각이 모두 동일함 | 필터, 검색, 북마크, 스크롤 위치 및 선택 행 전체 |
| 경로는 같지만 크기나 수정 시각이 변경됨 | 필터, 검색(행 위치가 달라졌을 수 있어 북마크와 스크롤 위치는 제외) |

- 최근 파일 목록에서 항목을 삭제하거나 `목록 지우기`를 실행하면 해당 파일의 저장된 작업 상태도 함께 삭제됩니다.

## 최근 파일

- 정상적으로 열린 파일은 최대 10개까지 `최근 파일` 목록(`recent-files.json`)에 기록되며, 빈 시작 화면이나 상단 바의 `최근 파일` 메뉴에서 바로 다시 열 수 있습니다.
- 여러 파일을 합쳐 연 경우에는 `첫 파일 외 N개` 항목 하나로 묶여 기록됩니다.

## 단축키

앱 상단 바의 `?` 버튼을 누르거나 입력란 밖에서 `?` 키를 누르면 전체 단축키 목록과 `기능 둘러보기`를 열 수 있습니다.

| 단축키 | 동작 |
| --- | --- |
| `Cmd/Ctrl+O` | 파일 열기 |
| `Cmd/Ctrl+R` | 열린 파일 다시 열기(작업 상태 유지) |
| `Cmd/Ctrl+S` | Android 기기에서 기록한 로그 저장 |
| `Cmd/Ctrl+F`, `/` | 검색 입력란으로 포커스 이동 |
| `Enter` / `Shift+Enter` (검색창) | 다음 / 이전 검색 결과 선택 |
| `Enter`, 더블클릭 (검색 결과 목록) | 상단 로그의 해당 행으로 이동 |
| `↑` / `↓`, `Shift+↑/↓` | 이전·다음 행 선택 및 범위 선택 |
| `Cmd/Ctrl+C` | 선택한 행 원문 복사 |
| `Cmd/Ctrl+B` | 북마크 추가·해제 |
| `F2` / `Shift+F2` | 다음 / 이전 북마크로 이동 |
| `Shift+F10` | 선택한 행의 컨텍스트 메뉴 열기 |
| `Alt+클릭` (레벨 버튼) | 해당 레벨만 단독 선택 |
| `Cmd/Ctrl` + `+` / `-` / `0` | 화면 확대 / 축소 / 100% 초기화 |
| `Esc` | 열린 요소 단계별 닫기 및 다중 선택 해제 |

`Esc` 키는 아래 순서대로 현재 열려 있는 요소를 하나씩 닫습니다.

1. 열려 있는 팝업 메뉴 또는 대화상자
2. 포커스가 내부에 있거나 자동 숨김 상태에서 펼쳐진 필터 패널
3. 하단 원문 상세 창
4. 고정된 필터 패널(열린 패널이 모두 닫힌 상태에서는 다중 행 선택을 단일 행 선택으로 해제)
